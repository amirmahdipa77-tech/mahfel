# دوز — بازی دوز آنلاین دو نفره

یک صفحهٔ وب تک‌صفحه‌ای (فارسی، راست‌به‌چپ) برای بازی **دوز** به‌صورت هم‌زمان، **بدون ثبت‌نام**، ساخته‌شده روی **Supabase Realtime**.

نسخهٔ منتشرشده: <https://amirmahdipa77-tech.github.io/mahfel/>

صفحهٔ قبلی (بازی مافیا) هم دست‌نخورده در [`mafia.html`](mafia.html) نگه داشته شده است.

## چه چیزی داخلش هست

- **بدون حساب کاربری**: فقط یک اسم کوتاه (اختیاری). هویت هر بازیکن یک شناسهٔ تصادفی است که در `localStorage` مرورگر ذخیره می‌شود و به‌عنوان توکن در درخواست‌ها فرستاده می‌شود.
- **ساخت بازی با کد**: با یک کلیک بازی ساخته می‌شود و یک کد ۶ حرفی می‌گیرید؛ لینک دعوت (`?g=CODE`) را برای حریف بفرستید.
- **بازی زنده**: حرکت‌ها با `postgres_changes` روی جدول `doz_games` و یک حلقهٔ همگام‌سازی هر ۱٫۸ ثانیه (پشتیبان) جابه‌جا می‌شوند.
- **قواعد کامل**: نوبت‌ها، تشخیص سه‌تایی در ردیف/ستون/قطر، مساوی، امتیاز دست‌ها و «دست بعد» با تأیید دو طرف.
- **حالت تماشاگر**: اگر کد بازی پر باشد، تخته فقط خواندنی باز می‌شود.

## پشت صحنه

منطق بازی کامل سمت دیتابیس و در توابع `SECURITY DEFINER` اجرا می‌شود؛ صفحه فقط این توابع را صدا می‌زند:

| تابع | کار |
| --- | --- |
| `doz_create(p_token, p_name)` | ساخت بازی و کد دعوت |
| `doz_join(p_code, p_token, p_name)` | پیوستن با کد (یا برگشت به بازی قبلی با همان توکن) |
| `doz_state(p_game_id, p_token)` | وضعیت تخته، نوبت، امتیاز و سمت شما |
| `doz_move(p_game_id, p_token, p_cell)` | ثبت حرکت با اعتبارسنجی نوبت و خانه |
| `doz_rematch(p_game_id, p_token)` | درخواست دست بعد (با تأیید هر دو بازیکن) |
| `doz_leave(p_game_id, p_token)` | آزادکردن صندلی بازیکن دوم |

جدول `public.doz_games` با RLS فعال است: خواندن برای همه (`anon`) باز است تا Realtime کار کند، ولی **هیچ سیاست نوشتن مستقیمی وجود ندارد** — همهٔ تغییرها فقط از طریق توابع بالا انجام می‌شود.

## اجرا روی سیستم خودت

`index.html` کاملاً مستقل است:

```bash
python3 -m http.server 8000
# سپس http://localhost:8000
```

برای اتصال به پروژهٔ Supabase خودت، مقدارهای `SB_URL` و `SB_KEY` بالای `<script type="module">` را عوض کن.

## انتشار روی GitHub Pages

این مخزن روی شاخهٔ `main` و از ریشهٔ پروژه با GitHub Pages منتشر می‌شود؛ هر push روی `main` سایت را به‌روز می‌کند.

## نکتهٔ امنیتی

کلید عمومی (anon) در صفحه قابل مشاهده است و این طبیعی است؛ امنیت از توابع سمت دیتابیس می‌آید. چون بازی بدون حساب است، هر کسی که شناسهٔ بازیکن یک نفر را داشته باشد می‌تواند به‌جای او حرکت کند؛ برای بازی دوستانه مناسب است، برای مسابقهٔ رسمی نه. برای پروژه‌های جدی‌تر: محدودسازی نرخ درخواست و افزودن احراز هویت واقعی را در نظر بگیر.
