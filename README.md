# چهارتایی — بازی آنلاین دو نفره (چهار در یک ردیف)

یک صفحهٔ وب تک‌صفحه‌ای (فارسی، راست‌به‌چپ) برای بازی **چهارتایی / Connect Four** به‌صورت هم‌زمان، **بدون ثبت‌نام**، روی **Supabase**.

نسخهٔ منتشرشده: <https://amirmahdipa77-tech.github.io/mahfel/>

صفحه‌های قبلی هم نگه داشته شده‌اند: [`doz.html`](doz.html) (دوز) و [`mafia.html`](mafia.html) (مافیا).

## چه چیزی داخلش هست

- **بدون حساب کاربری**: فقط یک اسم کوتاه (اختیاری). هویت بازیکن یک شناسهٔ تصادفی است که در `localStorage` می‌ماند و به‌عنوان توکن در درخواست‌ها فرستاده می‌شود.
- **ساخت بازی با کد**: یک کد ۶ حرفی می‌گیری و لینک `?g=CODE` را برای حریف می‌فرستی.
- **بازی زنده و نرم**: اشتراک `postgres_changes` روی جدول بازی + Presence برای دیدن آنلاین بودن حریف + حلقهٔ پشتیبان هر ۱٫۴ ثانیه. مهره با انیمیشن می‌افتد، ستون‌های مجاز برجسته می‌شوند، چهارتایی برنده علامت می‌خورد و در پایان کاغذرنگی و صدا دارد.
- **حرکت بی‌درنگ**: مهره همان لحظهٔ کلیک می‌افتد (optimistic) و بعد تأیید سرور جایگزینش می‌شود؛ اگر سرور رد کند، تخته به حالت درست برمی‌گردد.
- **جزئیات**: امتیاز دست‌ها، «دست بعد» با تأیید دو طرف، حرکت با کلیدهای ۱ تا ۷، صدا قابل خاموش‌کردن، احترام به `prefers-reduced-motion`، کاملاً واکنش‌گرا.

## معماری امنیتی

طراحی طوری است که **کلاینت هیچ اختیاری روی قواعد بازی نداشته باشد**:

| لایه | کار |
| --- | --- |
| RLS روی `chahar_games` | فقط `SELECT` برای `anon`؛ هیچ سیاست نوشتن وجود ندارد |
| مجوزها | `INSERT/UPDATE/DELETE/TRUNCATE` از `anon` و `authenticated` گرفته شده |
| تغییرات | فقط از طریق شش تابع `SECURITY DEFINER`: `chahar_create`، `chahar_join`، `chahar_move`، `chahar_state`، `chahar_rematch`، `chahar_leave` |
| اعتبارسنجی | نوبت، پر بودن ستون، وضعیت بازی و تشخیص برد **داخل دیتابیس** حساب می‌شوند؛ کلاینت فقط نمایش می‌دهد |
| توکن | فقط **هش SHA-256** توکن در جدول ذخیره می‌شود؛ خواندن جدول هیچ توکنی را لو نمی‌دهد |
| محدودیت نرخ | جدول `chahar_rate` با سقف ساخت/پیوستن/حرکت در بازهٔ زمانی؛ جدولش برای `anon` غیرقابل خواندن است |
| ورودی‌ها | نام بازیکن سمت سرور پاک‌سازی و به ۱۶ کاراکتر محدود می‌شود؛ کد بازی با الگوی سخت‌گیرانه بررسی می‌شود |
| توابع داخلی | `EXECUTE` توابع کمکی (`_chahar_hash`, `_chahar_rate`, `_chahar_code`, `_chahar_name`, `_chahar_check`) از `anon` گرفته شده |
| نگهداری | بازی‌های قدیمی‌تر از ۳ روز و ردیف‌های کهنهٔ محدودیت نرخ، خودکار پاک می‌شوند |

با این حال، صادقانه: هیچ سیستمی «نفوذناپذیر» نیست. چون بازی حساب کاربری ندارد، توکن بازیکن یک «Bearer» است؛ هر کسی که توکن یک نفر را در دست بگیرد می‌تواند به‌جای او حرکت کند (توکن‌ها دیگر از دیتابیس قابل خواندن نیستند، ولی روی دستگاه خود بازیکن هستند). برای بازی دوستانه کافی است؛ برای مسابقهٔ رسمی باید احراز هویت واقعی، CAPTCHA و محدودیت نرخ سمت لبه (WAF/Cloudflare) اضافه شود.

## پشت صحنه

- جدول اصلی: `public.chahar_games` (تخته ۴۲ خانه‌ای به‌صورت `jsonb`، نوبت، وضعیت، امتیاز، هش توکن‌ها)
- جدول محدودیت نرخ: `public.chahar_rate`
- Realtime: `chahar_games` در publication قرار دارد و `REPLICA IDENTITY FULL` است.

## اجرا روی سیستم خودت

`index.html` مستقل است:

```bash
python3 -m http.server 8000
# سپس http://localhost:8000
```

برای اتصال به پروژهٔ Supabase خودت، `SB_URL` و `SB_KEY` بالای `<script type="module">` را عوض کن.
